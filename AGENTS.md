## 📋 Project Overview

**Name:** Word of Truth  
**Type:** Progressive Web App (PWA)  
**Purpose:** Personal Bible reader with Amharic and English translations  
**Tech Stack:** Next.js 16, TypeScript, Tailwind CSS, IndexedDB

### Key Features Being Built
- Offline Bible reading
- Search (Amharic + English)
- Bookmarks and verse highlighting
- Side-by-side translation comparison
- iOS PWA support (no App Store needed)

## 🔧 Technical Guidelines

### Next.js 16 + Turbopack
- **Important:** This is Next.js 16 with Turbopack (not webpack)
- **Config:** Use `turbopack: {}` in next.config.ts
- **Be aware:** Some webpack-specific packages may not work

### Styling Conventions
- **Primary:** Tailwind CSS
- **Dark theme first:** Use slate-900 for background, slate-800 for cards
- **iOS-style:** Rounded corners (rounded-xl), subtle borders, bottom nav
- **Colors:**
  - Background: `bg-slate-900`
  - Cards: `bg-slate-800`
  - Primary accent: `text-blue-400`
  - Secondary: `text-slate-400`

  // Component logic
  return (
    <div className="...">

### Bible Data Format

#### Amharic (from magna25/amharic-bible-json)
```json
{
  "book": "Genesis",
  "chapters": [
    {
      "chapter": 1,
      "verses": ["በመጀመሪያ...", "ምድርም ባዶ..."]
    }
  ]
}
```

#### English (KJV/WEB)
```json
{
  "book": "Genesis",
  "text": [
    {
      "chapter": 1,
      "text": ["In the beginning...", "And the earth..."]
    }
  ]
}
```

## 📱 PWA Guidelines

### Required for PWA
1. **manifest.json** - Already configured
2. **Service Worker** - Auto-generated by next-pwa
3. **Icons** - Need to add to public/icons/
4. **Meta tags** - Already in layout.tsx

### Testing PWA
```bash
# Build for production
npm run build

# Start production server
npm start

# Or deploy to Vercel
vercel --prod
```

### iOS PWA Quirks
- iOS PWAs have limited storage (can be cleared)
- No push notifications on iOS
- Use `viewport-fit=cover` for full screen
- Test on real device, not just Simulator

## 🧪 Testing Guidelines

### Before Committing
1. Run dev server: `npm run dev`
2. Check for TypeScript errors: `npx tsc --noEmit`
3. Test on mobile viewport (Chrome DevTools)
4. Verify no console errors

### Mobile Testing Checklist
- [ ] Touch targets are at least 44px
- [ ] Bottom nav doesn't overlap content
- [ ] Scroll works smoothly
- [ ] Modal fits on small screens
- [ ] Text is readable (minimum 16px)

## 🚨 Important Constraints

### Legal
- **DON'T** commit copyrighted Bible versions (NIV, NLT, ESV, NASB)
- **ONLY** use public domain versions (KJV, WEB, Haile Selassie Amharic)
- Keep Bible data in `.gitignore` if copyrighted

### Performance
- Bible JSON is ~5MB - lazy load by book
- Use React.memo for verse components
- Virtualize long lists if needed
- Cache aggressively with Service Worker

### Storage
- IndexedDB has limits (~50MB on iOS)
- Compress data if possible
- Clear old cache versions

## 📝 Code Conventions

### Naming
- Components: PascalCase (`Verse.tsx`)
- Hooks: camelCase starting with 'use' (`useBookmarks.ts`)
- Utils: camelCase (`bibleData.ts`)
- Types: PascalCase with descriptive names (`BibleVerse`, `Bookmark`)

### Imports Order
1. React/Next.js
2. External libraries
3. Internal components
4. Hooks
5. Utils/types
6. Styles

### Comments
- Explain WHY, not WHAT
- Use JSDoc for exported functions
- Mark TODOs with `// TODO:`

## 🎨 UI/UX Guidelines

### iOS-like Design
- Use SF Pro font (system font on iOS)
- Subtle shadows and gradients
- Smooth transitions (150-300ms)
- Bottom sheet modals
- Pull-to-refresh

### Accessibility
- Semantic HTML elements
- ARIA labels where needed
- Focus states for keyboard navigation
- Minimum contrast ratio 4.5:1
